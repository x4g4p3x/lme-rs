# Source provenance and compatibility policy

`lme-rs` is an independent Rust implementation of linear, generalized, and nonlinear mixed-effects modeling workflows. It is distributed under the MIT License in [`LICENSE`](LICENSE).

## Relationship to lme4

The project uses [`lme4`](https://github.com/lme4/lme4) as an important behavioral and numerical reference. Compatibility work may reproduce documented statistical methods, model parameterizations, formula conventions, public interfaces, and observable numerical behavior.

The MIT-licensed Rust source is not intended to incorporate or translate `lme4` source code. Contributions should be implemented independently from published mathematical descriptions, public documentation, independently derived designs, and black-box numerical comparisons. When compatibility with `lme4` is tested, reference outputs and the provenance of any third-party test assets should be recorded separately from the Rust implementation.

Using the same mathematical notation or algorithmic concepts does not imply shared source-code provenance. Names such as `theta`, `Lambda`, `Zt`, `RZX`, PIRLS, REML, Laplace approximation, and related mixed-model terminology are used to describe established statistical and numerical methods and to make validation easier to follow.

## Third-party test assets

Some repository test fixtures are exports or format-preserving derivatives of datasets distributed by `lme4` or R. They are not relicensed as MIT source code. Their exact paths, origins, and licenses are recorded in [`legal/fixture-provenance.json`](legal/fixture-provenance.json) and summarized in [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md).

GPL-licensed fixtures are kept in the Git repository for validation but are excluded from the published Rust crate package. The legal-compliance check verifies the effective Cargo package file list so that these assets cannot silently enter a crates.io release.

Synthetic fixtures generated by this project are identified separately and remain under the project license unless another notice says otherwise.

## Dependencies and binary distribution

Third-party Rust and native dependencies retain their own licenses. Binary-distribution considerations, including LGPL relinking information and native BLAS/MKL notices, are documented in [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md) and [`RELINKING.md`](RELINKING.md).

## Contribution policy

Do not submit source code copied from, mechanically translated from, or generated by asking a tool to translate GPL-licensed `lme4` implementation code into Rust. If a contribution is based on a third-party implementation rather than on published mathematics, documentation, or observed behavior, disclose that provenance before submission so its licensing can be reviewed.

This file documents project provenance and contribution policy; it is not legal advice.
